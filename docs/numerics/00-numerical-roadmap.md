# Numerical development as a sequence of evidence gates

## Outcome and prerequisites

The numerical program should produce an engine whose approximation errors can
be distinguished from uncertainty in the physical model. Its outcome is not just
an audio file. It is a chain of reproducible evidence: correct units, compatible
operators, a justified integration rule, bounded solver behavior, quantified
accuracy, and a documented physical validity envelope.

Prerequisites are the mathematical contracts, the continuum energy derivation,
and the repository's master roadmap. The local gates below do not replace
master phase identifiers in docs/ROADMAP.md. They give the numerical meaning of
completion within each relevant phase. None is a calendar deadline or an estimate
of effort.

## Gate A: analytic components

Begin with a one-degree-of-freedom oscillator, an ideal string, and a simply
supported stiff string. Implement analytic solutions independently from the
production stepping loop. An analytic model must accept SI inputs and expose
displacement, velocity, and energy, not only normalized audio.

Evidence consists of checked equations, dimensionally valid fixtures, limiting
cases, and a comparison between at least two independent evaluation methods.
For the oscillator, compare closed form with a matrix exponential or high-accuracy
reference. For the string, compare modal frequencies with the continuum formula.
Resolve critical damping and zero-frequency limits explicitly.

Reject this gate if a test's “expected” value is generated by invoking the same
function under test. Reject a source citation that does not support the equation
or whose notation has been copied without units. Analytic component work can
proceed without claiming any physical parameter represents a real setar.

## Gate B: spatial operator integrity

Assemble small mass, stiffness, and damping matrices. Confirm boundary conditions,
symmetry or weighted self-adjointness, expected nullspaces, positivity, and exact
finite-grid eigenvalues where available. Compare the optimized stencil against
the matrix action on deterministic nontrivial vectors.

Evidence must include endpoint cases and the smallest supported mesh. An interior-
only test is inadequate because the bridge and frets interact strongly with
boundaries. Test interpolation and force injection as a pair through their
work identity. A good interpolation error curve does not compensate for a
nonadjoint injection operator.

Reject a discretization whose physical force changes with grid count, whose
boundary stencil is undocumented, or whose stiffness is made positive through an
unexplained diagonal offset. A correction that changes the physical problem must
be described as a modeling choice, not a numerical repair.

## Gate C: fixed-coefficient time stepping

Select one exact update equation and derive its amplification factors and discrete
energy. The explicit backward-gradient-loss scheme and the centered-loss scheme
are separate variants. Their coefficients, temporal order, and stability criteria
must remain separate in code and documentation.

Evidence includes single-mode frequency and decay tests, an energy ledger,
stability-margin checks, deliberate unstable-parameter tests outside production,
and temporal refinement at fixed spatial discretization. An update must not be
declared second order because its most visible derivative is centered.

This gate should produce a reference harness with deterministic initialization
and raw physical state output. It should not yet include arbitrary model retuning,
changing boundaries, or contact state corrections. Those operations can obscure
a basic integration error.

## Gate D: passive interconnection

Connect simple components through one power port before connecting the entire
instrument. Start with two masses and a spring, then string and lumped support,
then a string and a passive modal body. Verify equal and opposite forces and
synchronized work.

Evidence is a total-system energy balance, individual port work cancellation,
coordinate-transform covariance, and convergence of the joint response. A model
that exports bridge force but never accepts bridge motion does not pass a
bidirectional coupling gate. It may remain a useful reduced experiment, clearly
labeled as such.

Reject undocumented sample delays in feedback paths, copied gains used to hide
unit errors, and observation filters mistaken for mechanical loads. If delayed
or partitioned coupling is proposed for performance, it receives an explicit
approximation study against the joint reference.

## Gate E: nonlinear contact

Introduce one conservative scalar contact with a known potential. Verify divided
differences, root bracketing, onset, release, and contact energy. Extend to several
coupled contacts only after scalar behavior is understood.

Evidence includes independent residual evaluation, work defects caused by finite
solver tolerance, iteration distributions, maximum admissible penetration, and
worst-case bounded runtime behavior. A Newton method's successful average case
does not establish a real-time operating envelope.

Reject a contact model that silently clips force, rescales energy, or returns a
partially converged state as a valid render. Fault containment is a product safety
mechanism, not evidence of numerical correctness. Preserve rejected fixtures so
the failure can be reproduced without a plugin host.

## Gate F: time-varying physical controls

Add retuning, finger motion, changing contact normals, and any mesh changes one
operation at a time. Identify the corresponding external work or state-projection
energy. Keep the string domain fixed where possible while constraints evolve,
because deleting a string segment deletes its stored state.

Evidence includes slow and abrupt control trajectories, repeated boundary
crossings, state continuity, projection diagnostics, and convergence with respect
to control sampling. Explain the physical meaning of every pitch parameter.
A virtual pitch knob that modifies an oscillator frequency is not equivalent to
tension adjustment unless the reduced model establishes that mapping.

Reject a control smoother used as the sole explanation of stability. Reject
resetting all string states on a fret event. Such resets remove sympathetic
vibration, afterlength motion, and mechanical memory that the physical model is
supposed to investigate.

## Gate G: accuracy and cost tradeoff

For each candidate solver, measure frequency error, decay error, transient error,
contact error, and computational cost over the intended parameter envelope.
Separate temporal, spatial, modal-truncation, interpolation, and nonlinear-solve
errors. At least one reference should be sufficiently different that it does not
share the candidate's likely failure mode.

Evidence should show error versus cost, not merely cost at one configuration.
An implicit method with a large stable step may still have unacceptable phase
error. A very fine explicit grid can violate its stability bound at a fixed
sample rate. A modal model can conserve energy while omitting contact compliance.

Proposed design budgets belong in a versioned requirements record. They are not
derived physical constants and should not be presented as established perceptual
thresholds without listening evidence. Change them through review rather than
silently relaxing a failing test.

## Gate H: production numerical envelope

Freeze the supported ranges for geometry, tension, loss, contact stiffness, force,
control speed, and internal sample frequency. Validate parameter conversion before
entering the audio callback. Preallocate memory, bound nonlinear work, and make
coefficient changes atomic at a documented physical boundary.

Evidence includes denormal behavior, nonfinite fault handling, platform-specific
numeric comparisons, event-order determinism, and callback worst-case profiles.
Linux, Windows, and macOS evidence must come from actual runs; a configured
workflow alone is not a run result.

Keep a strict diagnostic reference mode separate from optimized production mode.
The production mode may use SIMD, fused operations, or mixed precision, but each
change requires comparison against the reference in physical metrics. A bitwise
golden file is appropriate only for a controlled execution environment.

## Managing uncertainty without blocking progress

Unknown material or contact parameters do not prevent numerical verification.
Use explicitly synthetic fixtures with dimensions and rationale. They can expose
sign errors, boundary defects, and convergence failures without pretending to be
measurements. Conversely, numerical success does not justify replacing a missing
measurement with a plausible number in the instrument model.

Maintain separate uncertainty labels for measurement error, model discrepancy,
parameter identifiability, and numerical approximation. If a decay fit can trade
string damping against body coupling, report the ambiguity. If two integrators
disagree more than parameter uncertainty, resolve numerical error before fitting.

## Handoff format

Every numerical milestone should hand off an equation contract, implementation
location, executed test commands, physical fixtures, measured error tables,
runtime environment, known failures, and the next admissible experiment. Do not
hand off only a WAV and a statement that it sounds better.

The exact primary sources and derivations are in the mathematical chapters and
the scheme-specific chapters. The immediate next action is the explicit
stiff-string update, because its clear modal structure provides a useful test
bed for the rest of the numerical program.
