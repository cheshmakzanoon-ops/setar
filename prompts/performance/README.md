# Scoped performance and contact work briefs

These prompts are intended for a contributor who has read `AGENTS.md`, the
orientation, and the relevant technical chapters. They request bounded work with
observable evidence. They do not authorize unrelated repository changes,
publication, data acquisition without permission, or claims that an unimplemented
design already exists.

| Brief | Primary question | Required evidence |
| --- | --- | --- |
| [Persistent strings and events](01-persistent-state-and-events.md) | Does one event stream preserve four physical states and deterministic ownership? | Direct event traces, repeated-pluck continuity, block-partition tests, rejection tests. |
| [Finite nail reference](02-finite-nail-reference.md) | Does a selected contact model exchange work consistently and converge? | Derivation, independent small-system reference, gap/force/work traces, refinement and failure reports. |
| [Playability evidence pack](03-playability-evidence-pack.md) | Which sequence behaviors are actually implemented and supported? | Capability matrix, synthetic/measured separation, sequence corpus, permissions, practitioner-review questions. |

Run one brief at a time unless non-overlapping ownership and dependencies make
parallel work safe. The first brief can use a transparent synthetic mechanical
fixture while contacts are unfinished. The second must not insert an implicit
contact force into the explicit FDTD baseline without a new combined derivation.
The third must not fabricate measurements or practitioner opinions to fill a
report.

Each handoff should state what changed, what was tested, what failed, which
assumptions remain, and the smallest next action. Passing a numerical test,
rendering a waveform, or compiling on one platform supports only the corresponding
claim. None by itself establishes high-fidelity Iranian setar synthesis.
